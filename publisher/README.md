# Public publisher MVP

Standalone Next.js App Router (Node) server. Django owns writes, models and migrations. This process reads PostgreSQL directly; no public request calls Django APIs. Start with `npm ci && npm run dev` in this directory and provide `PUBLISHER_DATABASE_URL` for a PostgreSQL role granted SELECT only on the two webpages tables. Point a development hostname at the app and register that hostname on a Django root page. No database credentials are needed for tests, typecheck or build. Keep the database role read-only even though the client also requests `default_transaction_read_only=on`.

The path resolver selects an exact hostname in PostgreSQL, falling back to `*` or `default`, then walks parent/slug within that root's tenant. All reads for a request use one read-only, repeatable-read snapshot. Root slug is silent for hostname roots. It selects the effective, unexpired version by descending effective date and version number. Dynamic path patterns return 404. The contract is `layout`, normalized `slots`, `context` (`mode: public`, `preview: false`) plus title/description. Database IDs are strings because Django uses 64-bit IDs. This app renders only static Headline, Hero and Content widgets as escaped text. Rich HTML content and unsupported widgets are intentionally not rendered. The existing editor/iframe preview and `EASY_WIDGET_REGISTRY` are untouched. This is a limited public slice, not a replacement for the entire Django renderer.

Still required for parity: widget inheritance, theme/layout inheritance, path pattern registry, dynamic object-storage/media/navigation resolvers, scheduled publication cache/invalidation, preview tokens and forms. Also validate production hostname routing, shared styling, rich HTML sanitization, and representative real data before changing live traffic. No schema changes or deployment configuration are included.
