# Image versions

Replacing an image in Media Manager keeps its UUID and writes the replacement to a new object key. The previous bytes and metadata are recorded as a historical version. Restoring a version uploads a new object and makes that new copy current. The image's **Protected from cleanup** setting prevents both manual version cleanup and permanent deletion.

Designer draft image uploads use separate version series attached to the theme. A replacement follows the previous image object rather than the position of its layout. Restoring one changes only the draft; publishing is still required before that draft change appears on the site. Deleting a theme retains its registered version series under the tenant, including protected images; unprotected versions remain subject to manual cleanup. Images selected from Media Manager use the media UUID route, so those images follow the current Media Manager version. When importing preview content, ECEEE converts only unambiguous tenant-owned library images to UUID references. Other image references remain unchanged.

Tenant administrators can preview and run manual cleanup from Media Manager. Enter a whole number of years from 1 to 100. The preview lists eligible historical objects and total bytes. Cleanup checks each object again before deleting it. Eligibility requires a superseded version older than the threshold, an unprotected image, no other storage owner, and no stored path reference in ECEEE pages, themes, Designer drafts, revisions, or export jobs. An object-storage failure leaves the version record so the run can be retried. External direct links to an object cannot be detected and are not protected by the reference scan.

Existing current Media Manager images acquire version number 1 through the schema migration without changing their stored objects. Existing Designer draft objects found in persisted snapshots are registered conservatively. Files overwritten before this feature cannot be reconstructed.

Before enabling manual cleanup on an upgraded tenant, preview legacy reference conversion with `python manage.py backfill_media_image_references --tenant TENANT_IDENTIFIER`. Run the same command with `--apply` after reviewing the reported row count. It rewrites only unambiguous stored media image URLs in live pages, page versions, objects, themes, and Designer drafts. Ambiguous references remain unchanged. Designer revisions and completed export snapshots remain untouched so their recorded history is preserved; cleanup still treats their object paths as references.
