# CMS interface languages

The CMS and help pages use English (`en-us`) unless the user's first browser language is Swedish (`sv` or `sv-*`). Profile → Language can save `English` or `Svenska` as an account-wide override; `Default` clears that override and follows the browser again. Unsupported browser languages fall back to English. The current-user API returns `preferredLanguage` and accepts `PATCH /api/v1/utils/current-user/` with `preferredLanguage` set to `""`, `"en-us"`, or `"sv-se"`.

English is the source language for new CMS interface copy. Static JSX text and the `title`, `placeholder`, `aria-label`, and `alt` attributes in admin pages and components use the Swedish catalog at `frontend/src/locales/sv.json`. Older Swedish-only static labels use `frontend/src/locales/en.json` to provide an English default. Run `node scripts/extract-cms-copy.cjs` from `frontend/` to list source strings when the UI changes. Dynamic labels use `cmsText` explicitly; `frontend/src/utils/cmsCopy.js` contains reviewed overrides for navigation and important actions. The build-time transform excludes widget rendering and other non-admin paths so tenant website content is not localized with the editor's preference.

Help pages use the same effective language by default. Their existing `?lang=en` and `?lang=sv` links remain explicit, page-local overrides. Maintained Swedish guides take precedence; the catalog supplies fallback translations for other guide titles, summaries, steps, and narration. The help script editor still edits each guide's language-specific source files.
